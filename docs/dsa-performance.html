DSA performance

How fast compiled Pun (.pind) runs classic data-structure and algorithm code: 14 algorithms for sorting, searching, Fibonacci and prime numbers, each at several sizes. Every PUN release is measured the same way on the same machine, so the versions can be compared directly.

Versions

How it's measured

  • The test page is chowk/sample_dsa. Every test starts from the same seeded input, so each version gets exactly the same work.
  • Each release runs the page as a compiled .pind on its own Pun Server, warmed up, on the same laptop.
  • One request runs a test many times in a row (the r parameter), so even quick tests take long enough to time. The time shown is the fastest of three to five requests, minus the time for an empty page, divided by the number of runs.
  • A new release is measured together with the release before it: one run that alternates between their two servers request by request, so both see the same conditions.
  • Each test counts its own steps (comparisons, writes and calls) and checks its answer. Every version made exactly the same number of steps in every test, and every answer was correct.
  • Averages are geometric means, so a test that takes a long time doesn't outweigh a short one.
  • The times come from one laptop. Compare the versions with each other; your own machine will give different absolute times.

Run it yourself

From the repository folder, build the test page and start the server:

java -jar target/pun-server.jar build chowk/sample_dsa
java -jar target/pun-server.jar serve chowk

Then open http://localhost:8080/sample_dsa_pind/ and pick an algorithm and size, or go straight to one, for example http://localhost:8080/sample_dsa_pind/?algo=quick&n=2000.
